# Recursive Factory · 递归工厂

[English](README.md) · **简体中文**

把整座工厂装进一个方块：内部可以扩容、嵌套，外部直接连接物流与动力，还能实时查看微缩预览。

**Minecraft 1.21.1 · NeoForge 21.1.249+ · Create 6.0.10+ · Java 21**

## 功能一览

| 功能 | 你可以做什么 |
| --- | --- |
| 口袋工厂 | 一个入口对应一格 16 × 16 × 16 的房间，单格净空为 14 × 14 × 13。 |
| 三维扩容 | 在入口旁边、上方或下方继续放入口，房间会按摆放形状合并。 |
| 工厂嵌套 | 在工厂里再建工厂，退出时逐层返回。 |
| 穿墙传输 | 物品、流体、红石与旋转动力直接连接内外，无需切换模式。 |
| 实时预览 | 入口框内以 1:16 比例展示房间，包括实体和受支持的机器。 |
| 蓝图复制 | 用机械动力蓝图保存工厂，再由蓝图大炮逐步建造，包含嵌套房间。 |
| 远程展示 | 绑定单向预览方块，在其他位置或维度查看指定房间格子。 |

## 快速上手

1. 在客户端和服务端安装本模组与 **机械动力（Create）**。
2. 合成入口：工作台四角放 **4 个同色混凝土**，四条边放 **4 个黑曜石**，中央放 **1 个末影之眼**。支持全部 16 种颜色。
3. 放下入口，**空手右键进入**，在里面搭建机器。
4. **右键任意工厂屏障离开**，回到进入前的位置。
5. 在入口相邻位置继续放置即可扩容；在房间里放入口即可创建嵌套工厂。

相邻入口沿用同一座工厂的颜色。扩容会检查工厂维度的空间边界，并避开其他工厂。

## 连接物流与动力

入口的一个面对应房间的**同方向墙面**：例如从入口北面输入，物品会从房间北墙进入。扩容后，每个入口仍然只连接自己那一格房间。

- **物品、流体**：外侧接漏斗、机械动力漏斗、管道或泵；内侧把接收容器紧贴对应墙面。内外均可输入和输出。
- **旋转动力**：外侧接入口，内侧把轴或机器贴在对应的屏障墙上。
- **红石**：向一端输入，另一端的对应面输出信号。
- **电力（可选）**：安装 **Create: Electro Energetics** 后，在入口和对应内墙上放置连接器，再向生成的表面节点接线。每个面内外各支持一个节点，可用机械动力扳手拆除。

接线和机器尽量避开墙角。扩容后打通的内部边界不会转接到其他格子的外墙。目前不支持机械动力的包裹物流。

## 复制与打印

**生存模式**：使用机械动力的**蓝图与笔**框选工厂入口并保存蓝图，部署后再放入**蓝图大炮**。给大炮提供火药与相邻材料容器后，入口先出现，内部随后逐块建造。缺料会暂停，补齐后继续；进度与已抓取的内容随存档保存。

**创造模式**：对准入口按中键，放置得到的方块即可复制。每次放置都会读取来源工厂的最新内容，连同相连入口与嵌套工厂一起展开；已放下的副本独立运行。来源不存在或展开位置受阻时，放置失败。

复制会保留替换后的地板和地板空洞；未改动的默认地板由房间自动生成，不额外计入大炮材料。空白蓝图右击入口不再抓取工厂。蓝图最多抓取 **8 层嵌套**，遇到循环引用会拒绝复制。安装 CEE 后，内部节点和电缆也会保存；连向房间外部的线缆不包含在内。

## 单向预览方块

手持**单向预览方块**右键入口绑定，再放到想查看的位置。微缩模型显示在薄底座上方，保持来源方向，各面可见；它只有展示功能。

合成方式：第一行中间放玻璃；第二行放「铁锭、末影之眼、铁锭」；第三行放「铁锭、平滑石、铁锭」。

## 加载与配置

入口区块加载时，内部房间保持运行。玩家在嵌套工厂内时，会逐层维持入口链加载；预览方块附近有人观看时，也会保持来源房间运行。不再需要时释放临时加载请求。

配置文件：`config/recursivefactory-common.toml`

| 配置项 | 默认值 | 作用 |
| --- | --- | --- |
| `room.repairBrokenFloor` | `false` | 准备房间时补回缺失的棋盘地板。 |
| `power.linkEnabled` | `true` | 启用 CEE 电力传输。 |
| `power.linkResistance` | `10` | 输电链路每端电阻，单位 Ω。 |
| `power.linkResponse` | `0.5` | 输电链路每 tick 的响应比例。 |
| `power.linkMaxCurrent` | `1000` | 最大请求电流，单位 A。 |

Sable / Simulated 为可选兼容，可在预览中显示受支持的物理结构和绳子。从旧版 **32 格高房间**升级时，建议新建世界，避免房间结构不兼容。

## 开发构建

启动已有开发环境的测试客户端（需要 Java 21）：

```powershell
.\run-client.bat
```

启动脚本使用 Gradle 本地依赖缓存，避免远程 Maven 仓库不可达时卡在启动前的依赖检查；仍会编译最新源码。游戏目录为 `run/client/`，日志位于 `run/client/logs/latest.log`。

首次克隆或更换依赖后，先联网运行 `.\gradlew.bat runClient --console=plain` 下载所需文件。若出现 `No cached version ... available for offline mode`，也使用这条联网命令补齐缓存。

构建发布产物：

```powershell
.\gradlew.bat build --no-daemon --console=plain
```

产物位于 `build/libs/`。独立服务器回归的运行方式见[验证说明](tools/verification/README.md)。

入口模型、贴图与预览渲染设计参考了采用 MIT 许可的 Create: Pocket Factory 项目。
